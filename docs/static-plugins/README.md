# Static plugins: v1 proposal and WordPress compatibility

Status: **recommendation for review, not a shipped plugin API or a user-made decision**. Scope: [#29 / PR-09](https://github.com/depress-org/depress/issues/29). Audited source: `19f239e507bb9b4beaa8ff9273560ba6f2aa5360`. All source citations below are pinned to that revision, not floating line numbers. [Contract](contract-v1.md) · [fixture acceptance and executed evidence](acceptance.md).

## What a user can safely expect

A migrated static blog does **not** run WordPress PHP plugins. Some exported values can be preserved; some behavior can be replaced by build-time static output. Neither is compatibility with an installed WordPress plugin, its settings, PHP hooks, database tables, or version range. An XML export is not an installed-plugin inventory. No WordPress/PHP version compatibility is certified here.

Before cutover, review the per-item report, compare pages and media with the source, build the generated site and inspect its rendered HTML. A successful conversion or root-repository build alone is not proof of parity. Dynamic forms, checkout, accounts, membership and live database queries need separate services/product decisions, not a static-plugin checkbox. Keystatic's editor/server routes are also distinct from static reader pages; generated adapters already include server integrations ([scaffold:78–79](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/scaffold.ts#L78-L79), [AstroWind:141–155](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/themes/astrowind.ts#L141-L155)). This proposal adds no reader-time server.

## Recommendation and alternatives

| Approach | Advantage | Tradeoff | Recommendation |
|---|---|---|---|
| Only hard-coded migration helpers | Smallest immediate change; existing SEO/nav/redirect code stays intact | Cannot honestly describe those as an extensible plugin API | Keep as built-ins; document limitations now |
| Versioned, first-party, build-time token transformer | Real bounded extension point; deterministic static output; npm/TS conventions | Requires source inventory, token preservation and report integration first | **Recommended v1**, opt-in, no additional service/database |
| Arbitrary npm/Astro integrations or user code | Broad flexibility | Arbitrary code/install/build attack surface; not a WP compatibility layer | Outside hosted v1; manual local customization is not certified migration support |
| Run original PHP/WP plugins | Would require their runtime and dependencies | Contradicts the static reader-site boundary; new infrastructure/security scope | Not supported |

No marketplace, package auto-install, remote plugin registry, runtime API, billing commitment or new infrastructure is proposed. Do not move working core SEO/redirect/navigation logic into plugins merely to create a plugin count.

## WordPress support matrix, matrix version 1

Classes refer to **capability/data**, not all versions of a named plugin. `preserved-data` means only the specified value at the specified stage. `static-replacement` means a viable static technique; availability is explicit below. `manual-review` means incomplete/ambiguous parity. `unsupported-dynamic` cannot run on a static reader site. A single source item can have several classes/findings.

| Capability / evidence | Preserved WP plugin data today | Viable static replacement | Manual review / unsupported dynamic behavior |
|---|---|---|---|
| Yoast title + description | WXR keys `_yoast_wpseo_title`/`_yoast_wpseo_metadesc` extracted; SQL fills missing WXR values, **not overrides** ([parser:99–110,145–173](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/parser.ts#L99-L173)). Direct `transformPosts` writes both ([transform:145–158](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/transform.ts#L145-L158)) | Existing built-in frontmatter/meta mapping, **not a plugin** | CLI bridge is incomplete; stage 2 accepts SEO only if already in wp2md frontmatter; pages discard SEO title ([stage2:79–120](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/keystatic-transform.ts#L79-L120)). AstroWind uses SEO as visible title/excerpt; Rocket truncates to 100/200 chars ([AstroWind:35–60](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/themes/astrowind.ts#L35-L60), [Rocket:33–43](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/themes/rocket.ts#L33-L43)). Template variables, canonical/robots/schema/social fields and Yoast runtime analysis are not certified |
| ACF / public custom fields | Non-underscore keys become strings in `WPPost.customFields`; SQL public values merge below WXR values ([parser:92–110,166–173](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/parser.ts#L92-L173)) | Explicit per-site schema/field mapping is possible, **not implemented by v1** | Both output frontmatter builders omit arbitrary custom fields (same transform/stage2 citations above). Nested/attribute-dependent layout, widgets, Elementor metadata and executable assets are not supported generally. Record each unresolved occurrence, not only a console warning |
| WP gallery shortcode | Direct helper replaces gallery with a review comment and loses `ids` ([transform:92–93,135–140](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/transform.ts#L92-L140)) | **Conditional first v1 candidate:** ordered static image list using preserved gallery IDs and successfully migrated local assets; proposed, not shipped | Missing IDs/media or non-default attrs require review; no slideshow/lightbox/plugin JS is promised. | Forms, membership, comments, runtime search/personalization | No general preservation contract: WPPost and WPExport omit form submissions/comments/auth/plugin state ([core:12–60](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/core/src/index.ts#L12-L60)) | Static form shell/search index could be manual future replacements, **not offered here** | Submission/email/auth/moderation/live queries are `unsupported-dynamic`; integrations require separate approval and acceptance. Never silently turn gated private content into public static output |

### Cross-cutting output limitations (not new plugin features)

- `injectContent` emits pages only when `adapter.pagesDir` is set ([inject:133–159](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/theme-inject.ts#L133-L159)). Neither bundled adapter sets it ([AstroWind:20–34](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/themes/astrowind.ts#L20-L34), [Rocket:19–31](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/themes/rocket.ts#L19-L31)); having `mapPageFrontmatter` alone is insufficient.
- Attachment alt is parsed ([parser:50–62](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/parser.ts#L50-L62)), but stage-2 options do not consume the attachment map ([stage2:6–23](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/keystatic-transform.ts#L6-L23)). Copy counts are not proof of alt or image integrity; theme copy errors are swallowed ([inject:178–185](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/packages/wp-migrate/src/theme-inject.ts#L178-L185)). #18 owns this reporting correction.
- Existing README claims about all pages, ACF and full profiles are broader than this audited path ([README:32–41,183–207](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/README.md#L183-L207)). Treat this document as the bounded compatibility description, not a certification of those claims. #19/#20 own wider release reconciliation.

## Why only a conditional gallery candidate?

Source/product evidence is the explicit static-plugin goal in #29 and the existing gallery placeholder/test plus ROADMAP's zero-silent-drop requirement ([ROADMAP:9–15](https://github.com/depress-org/depress/blob/19f239e507bb9b4beaa8ff9273560ba6f2aa5360/ROADMAP.md#L9-L15)). The audited sample contains **no gallery shortcode**. This is engineering justification for a small demonstrator, **not observed customer demand** or authorization to ship a feature bundle. Implement only after source inventory/report wiring and review of this proposal; otherwise ship truthful limits first. SEO/navigation/redirects are already built-ins and are not convincing “first plugins.”
