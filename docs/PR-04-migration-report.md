# PR-04 / #18 — versioned migration evidence

Schema version 1 is exported from @depress-org/core. The engine's report module is the canonical owner; plugins must add findings here rather than emit a competing report.

## Files and semantics

- source-manifest.json inventories every raw WXR item before the post/page parser filter, including original ID, ordinal-qualified key, source status/type, source metadata, source content and attachments. Source SHA-256 identifies the input bytes. This LOCAL file can contain private/draft source material: do not publish it or put it in public/.
- migration-report.json lists each item as migrated, skipped (nonpublished or separately accounted attachment), unsupported (published custom type), or failed. It records ID-linked shortcode/custom-field, author, exact Yoast, complete normalized prose, media/alt and redirect findings. It snapshots content/media/redirect bytes with SHA-256. qualityPassed is false for loss or unverified preservation, not just thrown exceptions.
- migration-report.md is a human projection, not an independently trusted QA input. A zero-drop sentence is never evidence.

The shared CLI/service emits reports after final theme injection. Valid sources that fail conversion get best-effort failed-item reports before the original typed error is rethrown. Invalid XML cannot produce a trustworthy inventory and rejects without claiming one.

All quality CLI checks require the manifest and report, recompute every item's evidence from current output, compare the complete report, and fail closed on missing/malformed/schema-mismatched/changed evidence. Per-item checks never accept unrelated redirect counts or arbitrary populated authors/descriptions. The job pipeline refuses done/deployment when qualityPassed is false, preserving report artifacts for inspection.

## Preservation and conservative limits

Existing wp2md/stage2 conversion remains the converter. Source post/page author and Yoast fields are bridged into its output (type-specific slug matching, no ambiguous metadata assignment). Unique attachment alt fills empty Markdown image alt; nonempty inline alt is not overwritten. Unused/unrepresentable alt, ambiguous media basenames, unavailable attachment bytes and source references are explicitly failed/unsupported, not success. Unsupported shortcode attributes and custom fields are retained in source-linked findings; no general plugin support is implied.

Duplicate IDs and same-collection case-folded duplicate slugs cannot claim one destination twice. Pages in scaffold are directory entries; theme pages are flat and themes without pagesDir fail visibly. Report reads reject unsafe paths and escaped symlink targets; this is not a replacement for #24 converter security or #25 worker isolation. Full normalized prose comparison is conservative: changed formatting that changes normalized text can need review rather than false-green migration.

Redirects retain existing generation logic and root compatibility files, and now additionally ship in public/_redirects and public/redirects.json so generated builds include the checked evidence. Destination mappings are verified per source ID; a generated route build remains a separate gate.

## Independent-review corrections and explicit limits

- Nonpublished post/page outputs are inspected rather than unconditionally skipped. Expected public collection files and static public paths fail quality regardless of a `draft` frontmatter label; unreadable/unsafe evidence fails closed. All item findings participate in quality, including nonpublished items. A fresh validator detects leaks introduced after report generation.
- Editable post drafts in `src/content/articles/_drafts/` have one narrow exception: current public source/config files must match the canonical scaffold byte-for-byte, including route/home/blog/category readers and their components. Unknown source files, changed readers, noncanonical layouts and unsafe symlinks reject the exception. Draft/editor bytes and proof files are hashed in the same schema-1 report. The scaffold writer/verifier share generators; no existing template bytes changed. This is not arbitrary-program analysis, signed provenance, a sandbox, or security approval: custom templates require independent exclusion evidence before support. It deliberately fails closed for unrecognized scaffold literals. Source manifests and editor storage must never be copied to `public/`.
- Each source image occurrence is matched to its corresponding local body image, in occurrence order for that local path within the same item. Nonempty inline alt must match that occurrence, not an attachment fallback or a token elsewhere. Frontmatter, another item's images, HTML comments (including commented Markdown), escaped Markdown, raw HTML and code examples are not inline-alt evidence. Destination image evidence uses the same pinned Markdoc parser as the generated `.mdoc` renderer, never regex tokens or HTML image tags (Markdoc renders raw HTML as text). The tokenizer explicitly matches Astro’s `allowComments: true`: bare `Markdoc.parse(string)` uses different defaults and is NOT sufficient, because it would count Markdown images inside HTML comments which Astro removes. Both commented-HTML and commented-Markdown actual generated-build negatives cover this difference. Only static image AST nodes without tags, parse errors or annotations prove alt; no dynamic/custom tag evaluation occurs. Other output formats currently fail closed for image preservation until their renderer is verified. Source HTML images are collected from parsed elements using the existing Turndown parser. This is a grammar-level proof for the canonical renderer, not arbitrary custom-renderer analysis.
- Body prose evidence now uses the pinned canonical Markdoc tokenizer (`allowComments: true`) and default built-in transform, then flattens only static visible render-tree text. Inline formatting is concatenated without artificial word boundaries; block/line breaks separate words. HTML comments contribute no text, image attributes/URLs and fence language labels never contribute prose, and code/escaped examples remain visible literals. Source HTML is separately parsed/flattened through Turndown without reparsing literal examples as active Markdoc. Only `.mdoc` is proven: unknown formats, parse/validation errors, custom tags, annotations/slots and variable/function attributes fail closed, including alongside otherwise retained prose. No content-supplied functions/custom renderers are executed. Punctuation/whitespace normalization remains deliberate; this is not a visual-layout/CSS proof for arbitrary templates. Eight actual generated body builds assert the nested `.prose > article` text separately from unchanged frontmatter/excerpt/source manifest, including fully/partly commented negatives and plain/formatted/retained-comment/code/escape positives. The existing required generated-site lane runs these controls alongside all nine image controls and privacy negatives.
- Zero-byte attachments fail with `empty-media`. A post-copy SHA-256 snapshots local nonempty bytes for later tamper detection; it does NOT establish equality to original remote/source bytes, MIME/signature validity, successful image decoding, absence of malicious content, or general image integrity. This offline verifier deliberately does not fetch source URLs or decode media.
- Generated integration negatives deliberately emit both draft and private items into the public collection, assert report+validator failure, and run actual Astro builds proving those controls really publish. A changed safe draft reader invalidates the exception. The final restored build excludes both controls; real cold consumer install/build and unchanged-lock reinstall/rebuild remain separate gates.
